--- Day 0: Cold Boot ---

Long before any of this was a website, it was a beige tower PC in an attic. You find it under a dust sheet, plug it in and flip the switch. The fans spin up, one LED starts blinking, and the screen stays black.

A sticky note on the case reads BOOT CHECKSUM IN REG A. DON'T FORGET IT. Underneath, in a different pen: forgot it.

The boot ROM is a tiny program (your puzzle input) for a processor with four registers, a, b, c and d, which all start at 0. It understands four instructions:

  • mov x y copies x (an integer or the value of a register) into register y.
  • inc x increases register x by one.
  • dec x decreases register x by one.
  • jnz x y jumps to the instruction y away (positive is forward, negative is backward), but only if x is not zero.

The program halts as soon as it tries to execute an instruction outside of the program. For example:

mov 3 b
inc a
inc a
dec b
jnz b -3

This adds 2 to a, three times. When it halts, register a contains 6.

Run the boot program. What value is left in register a when it halts?

--- Part Two ---

The checksum is accepted. The screen flickers on, a cursor blinks, and then the machine just sits there, thinking. Slowly. Very slowly.

On the front of the case there is a button labelled TURBO. Pressing it makes the boot ROM start with register c set to 1 instead of 0. The other registers still start at 0.

Your interpreter is going to need a coffee break. Possibly several.

With the turbo button pressed, what value is left in register a?
